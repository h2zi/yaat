# YAAT 架构与数据边界

本文描述未发布 v1 的实际实现，重点是账号切换不会丢失客户端的其他配置。

## 组件

```text
React 19 + TypeScript UI
   ├─ shadcn/ui New York + Tailwind CSS 4
   ├─ Radix Primitives
   └─ Recharts
   │ capability 授权的类型化 IPC
   ▼
Tauri / Rust
   ├─ Repository ─ SQLite 元数据与账号凭据
   ├─ Adapters ─── Codex / Claude Code / Claude Desktop
   ├─ Activation ─ 白名单字段补丁、原子替换与字段回滚
   ├─ History ───── 缺失与单向追加会话同步
   ├─ Launcher ──── 可见系统终端或隔离 Desktop 进程
   └─ Usage ─────── 本地 Token 元数据索引
```

前端 WebView 使用 Tauri 默认安全配置；Tauri capability 只绑定 `main` 窗口，不开放文件系统、Shell、HTTP、opener、系统钥匙串或事件权限。账号列表不携带凭据；编辑单个账号时，前端可通过独立命令按 ID 读取、回显并复制该账号的凭据。

## Tauri 组合与权限边界

`src-tauri/src/lib.rs` 是唯一的应用组合根。single-instance 插件必须先于其他插件注册；应用状态初始化成功后才注册到 Tauri managed state。

命令暴露采用三层同步白名单：`generate_handler!` 注册 Rust handler，`build.rs` 把同一组命令写入 Tauri `AppManifest`，`capabilities/default.json` 再只向 `main` 窗口授予对应权限。`src-tauri/permissions/autogenerated` 和 `src-tauri/gen/schemas` 是构建产物，不承载手工业务规则。

Rust 模块按职责分层：

```text
commands ── 输入验证、事务编排、稳定 IPC 错误
   ├─ app_state / db ────────── 状态、关系数据、账号凭据
   ├─ platform/* ────────────── 客户端发现、配置计划、凭据互操作
   ├─ activation/* ──────────── 字段所有权、CAS 原子发布、回滚
   ├─ history ───────────────── 会话扫描与增量同步
   ├─ usage/* ───────────────── 元数据解析、去重与日期聚合
   └─ launcher / process ─────── 受控进程启动、超时与存活检查
```

除公开的补丁引擎和共享 IPC contracts 外，模块不构成可供外部 crate 使用的应用 API。平台或存储细节不得泄漏到 React 组件；前端后端调用统一经过 `src/api.ts`。

## 平台状态

一个平台同时保存两个互不覆盖的引用：

- `global_profile_id`：当前确实写入客户端默认配置 / 凭据槽的账号；删除前必须先切换或停止全局管理。
- `last_managed_profile_id`：最近一次由 YAAT 成功打开的隔离账号，仅用于 UI 与历史目录提示；删除该账号时自动清空。

隔离启动不会改变 `global_profile_id`，全局切换也不会抹掉最近托管账号。因此“全局 A → 隔离 B”不会错误地把 A 当成已停用。

## 隔离启动

每个账号使用独立目录：

```text
~/.yaat/profiles/<platform>/<profile_id>/home
```

Codex / Claude Code 通过 `CODEX_HOME` / `CLAUDE_CONFIG_DIR` 使用该目录，并在用户选择的绝对项目目录中打开新的可见终端。macOS 使用 Terminal，Linux 使用系统 `x-terminal-emulator`，Windows 使用 Windows Terminal。动态参数逐项传递或严格 shell quoting；API Key 不进入命令行，而是直接写入隔离配置的客户端原生凭据字段。

YAAT 的 SQLite、隔离 profile、Codex model catalog 与备份都从唯一路径模块解析到用户 home 下的 `.yaat`。`YAAT_DATA_DIR` 只用于开发、测试和便携部署显式覆盖；旧 Application Support 目录不读取、不迁移、不删除。

Claude Desktop 使用独立 `CLAUDE_USER_DATA_DIR` 直接启动。官方账号捕获 `lastKnownAccountUuid`、经 Electron Safe Storage 解密的 OAuth Cache 和明确列出的认证 Cookie；Local Storage、IndexedDB、主题、扩展及其他 Cookie 不属于 YAAT。第三方直连 Provider 把凭据、认证类型、请求头、User-Agent 和模型写入隔离目录内 YAAT 自有的 config-library 条目。

## 全局切换

全局模式只有一份持久的“接管前基线”，没有逐次 switch journal、恢复状态机或重复的 managed-fields 表：

```text
确认客户端已退出
  → 解析实时配置并准备白名单字段补丁
  → 首次接管：保存字段 before 与原始凭据
  → 后续切换：保留原始 before，只更新最新 after
  → 原子提交配置
  → 官方账号：复制并读回验证目标私有凭据
  → 写入 global_profile_id 并立即返回
  → 可选历史增量任务进入后台队列
```

单次操作失败时，当前进程直接恢复本次切换前的凭据、回滚已经提交的字段补丁，并把数据库中的基线恢复到操作前状态。基线在外部写入前落库；后续全局应用会继续复用同一份首次接管基线，不增加单独的恢复状态机。

全局管理期间不能修改对应平台的 CLI 路径、配置根或活动 Provider 的地址、模型与凭据；名称和账号备注仍可编辑。需要更改执行配置时，先停止全局管理，再编辑并重新应用。

## 停止全局管理

显式停用执行：

1. 确认客户端已退出。
2. 从持久基线恢复原始官方凭据（若 YAAT 曾替换凭据）。
3. 重新读取当前配置，只把 YAAT 归属字段恢复到原始 `before`。
4. 在同一个 SQLite 事务中清空 `global_profile_id` 并删除基线，失败时两者都保留以便重试。

它不会删除账号、托管目录或历史，也不会回写整份旧配置。

## 配置补丁不变量

- 目标必须是绝对路径和大小受限的 UTF-8 TOML / JSON / JSONC。
- JSON 重复键、路径穿越非对象值和重叠归属路径会失败。
- 渲染前后执行语义 diff，白名单之外出现任何差异都会拒绝提交。
- 语义无变化时保持逐字节 no-op。
- 同目录临时文件同步后原子发布，并保留权限。
- 注释、键顺序、BOM、CRLF 与未知字段由 CST / `toml_edit` 路径补丁保留。

Codex 只接管模型 / Provider 选择字段、`model_providers.custom` 和可选 `model_catalog_json`；对象以显式 TOML 表多行写入，不压成 inline table。Claude Code 只接管 `env` 中的 Anthropic / Claude Provider 选择、直接凭据、模型映射和请求头字段；激活时会移除当前客户端配置中 YAAT 旧版遗留的 `apiKeyHelper`，但不会读取或迁移旧 YAAT 数据库。两者都不修改 permissions、MCP、插件、主题或其他未知字段。

Claude Desktop 官方账号只接管 `config.json` 中的 `lastKnownAccountUuid`、`oauth:tokenCache`、`oauth:tokenCacheV2` 和 Cookies 数据库中的认证 Cookie 行。Token Cache 与 Cookie 在捕获时由 Claude Safe Storage 解密，以可回显的账号快照保存到 YAAT SQLite；恢复时使用目标 Profile 的 Safe Storage 重新编码。3P 模式只接管默认配置的 `deploymentMode`、YAAT 固定 config-library 条目和 `appliedId`；恢复时保留管理期间新增的其他 library 条目。

## 凭据复制

API Key、Token、Codex / Claude Code / Claude Desktop 官方账号快照和全局恢复基线保存在 SQLite `account_data` 表中。账号列表只读取关系字段；显式编辑某个账号时才读取对应凭据。

官方账号创建可以粘贴 YAAT 的平台匹配凭据 JSON 并立即恢复到隔离 Profile，也可以留空创建为待登录账号。编辑时同一份 JSON 会完整回显，可复制到另一个官方账号或替换现有凭据。

Codex 当前账号快照包含 `auth_mode`、`OPENAI_API_KEY`、`tokens`、`last_refresh` 四个账号字段。解析器验证有效认证模式和必需 Token，但接受账号对象中的未来未知字段，也不对 `last_refresh` 的展示格式作无关限制。恢复时在实时文档上合并四个字段，保留 `agent_identity`、个人访问令牌、Bedrock 凭据和未来未知字段。

Codex 凭据存储：

- `file`：字段合并、原子发布、读回验证、直接回滚。
- `keyring`：不检查 CLI 版本号，按实际 `secret_auth_storage` feature 选择直接系统钥匙串或“钥匙串口令 + Age secrets 文件”。
- `auto`：明确无 Keyring 条目时才读取文件；Keyring 错误不会冒充缺项。
- `ephemeral`：无法跨进程复制，拒绝切换。

Claude Code 快照只包含 `claudeAiOauth`、`organizationUuid`、`trustedDeviceToken`、`enterpriseGateway`。`pluginSecrets`、MCP OAuth、design OAuth、gateway trust 与未知字段始终从实时 secure storage 保留。共享默认凭据槽与隔离 Profile 都不检查 CLI 版本号，写入后仍按账号字段读回验证。

Windows Credential Manager 的直接值上限不足时，Claude/Bun 使用 `#m` 元数据、`#0..` Base64 分块和 `#p` 未完成标记。YAAT 可在直接值和分块值之间双向切换，也可清除分块槽。Credential Manager 不提供跨条目事务，因此 YAAT 会先发布 `#p`，完成分块、元数据和旧条目清理后才移除标记；任何阶段失败都会尽力恢复先前逻辑值并报告失败阶段和回滚结果。若回滚也失败，`#p` 会继续使后续读取明确失败，避免把半写状态当作有效凭据。

Claude Desktop 快照包含账号 UUID、两套解密后的 OAuth Cache，以及 `sessionKey`、`sessionKeyLC`、`lastActiveOrg`、`routingHint`、`__Host-ant_trusted_device` 对应的明文 Cookie 值和必要元数据。全局运行期间刷新后的账号快照会在切走前回写对应 YAAT 账号。macOS 使用 Claude Safe Storage 钥匙串派生的 Electron `v10` AES-128-CBC 编解码；Windows 读取 `Local State` 中由当前用户 DPAPI 包装的 256 位密钥，并使用 Electron `v10` AES-256-GCM 编解码。Chromium Cookie 数据库 v24 的加密明文包含 `SHA-256(host_key)` 前缀，YAAT 在捕获时验证并移除、恢复时重新生成。读取到其他 Cookie 数据库版本但仍能完成解密、域名哈希校验和字段解析时，捕获结果携带一次性 warning；warning 不写入账号快照。写入未知 Cookie 数据库版本或遇到未知 Safe Storage 版本时仍会在修改账号配置前停止。

全局凭据基线使用三态语义：未接管、原账号存在、原账号为空。严格凭据捕获仍要求账号存在，用于导入来源与登录完成后的保存；全局槽捕获允许合法为空，但钥匙串错误、文件错误和凭据损坏仍然失败。恢复“为空”只移除账号归属字段，不覆盖实时文档中的其他字段。

## 本地凭据存储

- YAAT 不创建主密钥，也不在启动时访问系统钥匙串。
- `account_data.value` 直接保存凭据与恢复基线；本项目未发布，不保留旧密文 v1 数据库兼容层。
- 后端读取值后仍使用 secrecy / zeroize 包装敏感内存，调试输出不打印凭据。
- Codex、Claude Code 和 Claude Desktop 自身使用的 Keychain / Credential Manager / Safe Storage 只在捕获、切换或恢复对应客户端凭据时访问，与 YAAT SQLite 启动无关。

## 用量数据

扫描器只持久化平台、稳定事件键、时间、请求数和 Token 分类；不保存 Profile 归属，也没有提示词或回复列。历史同步后同一事件不会因为目录来源不同而被任意归到某个账号。

- Codex：`sessions`、`archived_sessions`、`.jsonl`、`.jsonl.zst`。
- Claude Code：`projects` JSONL，处理子代理、重放、初步 / 最终批次和缓存 Token。
- 源文件按路径、大小、mtime 和指纹增量索引；复制历史的同一逻辑事件只统计一次。查询最长 366 天并按 IANA 时区聚合，支持模型过滤、自动刷新和缓存命中率。
- Claude Desktop 与远程配额不在第一版统计范围。

## 会话历史

- 扫描不跟随目录中的符号链接，但允许用户配置的历史根本身是正常符号链接。
- 同名同内容跳过；缺失会话复制；一份会话严格扩展其他所有版本时使用最长版本更新目标；真正分叉报告冲突且不覆盖。
- Codex 首次统一和“重新统一”会幂等修正 JSONL / Zstd 中的两处 provider 元数据与 `state_5.sqlite.threads.model_provider`，统一为 `custom`；启用后不可关闭。
- Claude Code 只同步各配置根的 `projects` JSONL。
- Claude Desktop 只处理 `claude-code-sessions/<账号>/<组织>/local_*.json`，目标必须来自扫描结果；Chat / Cowork 不参与。
- 自动同步默认关闭。账号激活和隔离启动只投递后台增量任务，不在切换成功返回前枚举历史目录。Claude Code 关闭后只停止后续同步，不删除已复制会话。同步失败只更新状态，不撤销已经成功的账号操作。

## 当前限制

- Codex `keyring` / `auto` 依赖 CLI 报告 `secret_auth_storage` feature；若无法判断实际后端则拒绝操作。互操作 Docker 镜像中的固定 CLI 版本只是可重复测试基准，不是运行时门禁。
- Claude Desktop 不做本地协议转换；官方账号导入与全局切换只发布在 macOS / Windows，Linux 不是发布目标。
- Windows Docker 交叉检查覆盖 FFI 和条件编译；真实 DPAPI、Credential Manager 与系统钥匙串故障路径仍需要对应平台 CI。Docker 测试绝不访问宿主机凭据。

## Docker 验证

`docker/app-build.Dockerfile` 在容器内执行 workspace check、Clippy、`-D warnings` Rust 文档、Rust 测试、TypeScript/Vite 构建和 Tauri 无 bundle 构建；`docker/windows-check.Dockerfile` 交叉检查 `x86_64-pc-windows-gnu` 的全部 Rust targets。`scripts/test-codex-docker.sh` 使用 Codex `0.147.0` 和容器内 mock Responses 服务验证严格配置、直接凭据、官方账号字段复制和无关配置保留；Claude Code 互操作基线是 `2.1.226`。容器运行阶段禁网并移除 capabilities。
